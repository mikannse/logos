# PRD: Logos — AI 名词知识图谱与演化平台

*给你的好奇心装一张知识地图*

## 1. 愿景

Logos 是一个 **AI 驱动的名词知识图谱与演化平台**。你把一个名词扔进去，它自动给你三样东西：

1. **一张关系图谱**——这个概念周围有哪些人、事、思想？它们怎么关联的？
2. **一条演化时间轴**——这个概念从哪来？经历了什么关键变化？下一步可能往哪去？
3. **一个 AI 对话窗口**——对这堆关系问任何问题，不用自己翻十几个标签页。

**我们解决的问题：** 碎片时代，我们太擅长收集信息了，太不擅长看见全景。搜一个名词 → 点开 Wikipedia → 遇到新概念再点开 → 半小时后十七个标签页开着，大脑像一团乱麻。现有工具要么是手动的（Obsidian），要么是企业级的（Neo4j），要么没有探索式界面（Diffbot）。**没有产品能让你输入一个词，就自动得到一张带时间轴、能对话的知识地图。**

Logos 不是又一个知识管理工具。**是专属的知识侦探。** 你丢线索，它帮你在五分钟内把拼图拼起来。

## 2. 目标用户

### 2.1 Jobs To Be Done

- **理解一个陌生名词：** 当遇到不熟悉的概念时，快速获得全景认知，而非零散链接
- **发现隐藏关联：** 知道 A 和 B 各自是什么，但想知道它们之间有什么关系
- **追溯演化脉络：** 理解一个概念的历史变迁和关键转折
- **深度追问：** 对已经看到的关系图谱提出进一步问题，无需切换工具
- **多人协作分享：** 将发现的关联导出/分享给团队或读者

### 2.2 非目标用户 (v1)

- **企业级数据团队**（需要自定义图查询、批量导入、Cypher 接口的开发者）
- **学术研究者**（需要精确引用、文献管理、学术图数据库集成的方向）

### 2.3 关键用户旅程

#### UJ-1: 小明理解一个陌生名词

- **人物+情境：** 小明，普通互联网用户。刷即刻时看到「涌现」这个名词，不完全理解但不想开十几个标签页
- **入口：** 未登录状态，打开 Logos 首页，看到一个搜索框
- **路径：**
  1. 在搜索框输入「涌现」
  2. 系统返回关系图谱（强关联：混沌理论、自组织、生命起源、群体智能；弱关联：AI、意识、经济现象）
  3. 看到图谱的瞬间，小明对"涌现"的语境有了直观感受
  4. 时间轴展示：提出→ 生物学验证→ 跨学科扩散 → 当前热门前沿
  5. 小明看到一个感兴趣节点「自组织」，悬停后弹出摘要
- **高潮：** 小明发现「涌现」和「复杂系统」原来有强关联，这不是一个孤立概念
- **解决：** 小明理解了名词的核心含义和位置，关闭页面
- **边界情况：** 输入非常冷门的词 → 系统提示「此概念公开数据较少，图谱可能不完整」，仅展示 Wikidata 已有数据

#### UJ-2: 林记者调查人物关系

- **人物+情境：** 林记者，科技记者。某科技公司收购了一家 AI 初创团队，她想写深度报道
- **入口：** 已访问 Logos，在搜索框输入初创公司创始人的名字
- **路径：**
  1. 关系图谱展开，看到创始人之前创办过另一家公司——那家公司被收购了，收购方正是今天的主角
  2. 图谱上两条线连起来，关联一目了然
  3. 时间轴拖回五年前：创始人的学术背景 → 第一次创业 → 产品上线 → 团队扩张 → 被收购
  4. AI 对话：「这位创始人和被收购公司的 CTO 之前有没有合作过？」
  5. AI 在图谱里跑了一圈：「他们在 X 大学同一个实验室待过两年」
- **高潮：** 林记者得到一个独家选题的角度——原来收购早有渊源
- **解决：** 林记者导出图谱截图，写入报道框架

#### UJ-3: 王总研究领域趋势

- **人物+情境：** 王总，投资者。对「量子计算」这个赛道需要快速建立认知
- **入口：** 搜索「量子计算」
- **路径：**
  1. 图谱展示：核心概念（量子比特、叠加态、纠缠态）、关键人物（Shor、Grover）、关键公司（IBM、Google、IonQ）
  2. 时间轴：1982 Feynman 提出 → 1994 Shor 算法 → 2000s 物理实现 → 2019 Google 宣称量子霸权 → 2024 纠错突破
  3. 王总点击一家创业公司节点，看到其融资时间线、核心技术路线
- **高潮：** 王总发现该赛道上中国和美国的技术路线选择了不同方向
- **解决：** 王总整理图谱信息作为投资备忘录

#### UJ-4: 阿花积累创作素材

- **人物+情境：** 阿花，独立内容创作者。想写一篇关于「赛博朋克」的深度长文
- **入口：** 搜索「赛博朋克」
- **路径：**
  1. 图谱展示：核心概念（高科技低生活、控制论、反乌托邦）、代表作品（Neuromancer、银翼杀手、攻壳机动队）、关键主题（AI觉醒、义体、巨型企业）
  2. 时间轴：1980s 文学起源 → 1990s 电影爆发 → 2000s 游戏扩展 → 2010s 概念普及 → 2020s 现实交织
  3. 阿花点击 Neuromancer 节点，看到它如何影响后续作品
- **高潮：** 阿花发现了一个有趣的关联——赛博朋克与日本泡沫经济的关系
- **解决：** 阿花做了一系列截图和笔记，作为文章的结构框架

## 3. 词汇表

- **名词 (Noun)** — 用户可以搜索的任意实体，包括人物、概念、技术、产品、组织等。图谱的基本单位。
- **关系图谱 (Relationship Graph)** — 名词之间的关联网络，以力导向图（Force-directed Graph）可视化呈现。节点=名词，边=关系类型（影响、隶属、创作、发现等）。
- **演化时间轴 (Evolution Timeline)** — 名词及其关联概念随时间变化的关键里程碑序列。支持拖拽缩放。
- **AI 对话 (AI Chat)** — 基于图谱上下文的 LLM 问答界面。用户可以追问、深挖、对比。
- **关联强度 (Relation Strength)** — 实体间关系的紧密度量，影响图谱中边的粗细/显眼程度。基于多源交叉验证得出。
- **置信度 (Confidence Score)** — 每个事实和关系标注的可靠性评级（高/中/低）。低置信度标注来源和不确定原因。
- **渐进式信息密度 (Progressive Information Density)** — 先展示全景，用户想看细节再深入的分层展示策略。
- **分层知识模型 (Layered Knowledge Model)** — 四层结构：核心卡片 → 关系图谱（广度） → 关键历程（深度） → 隐藏洞察（跨领域关联）。
- **人物优先原则 (Person-First Principle)** — 人物作为默认探索入口的设计原则。人物节点在搜索排名和展示中优先。
- **GraphRAG** — 结合知识图谱与检索增强生成（RAG）的技术架构。三层：图遍历（L1）→ 语义搜索（L2）→ LLM 推理（L3）。

## 4. 功能特性

### 4.1 搜索与名词入口

**描述：** 平台的核心入口。用户在搜索框输入任意名词，系统自动识别实体类型（人物、概念、技术等）并返回图谱数据。支持中英双语输入。实现了 UJ-1, UJ-2, UJ-3, UJ-4。

**功能需求：**

#### FR-1: 名词搜索

[用户] 可以在搜索框输入名词 [查询条件] 并获取图谱数据。支持中英文输入，自动识别实体类型。

**可验证结果：**
- 搜索英文"emergence"和搜索中文"涌现"返回同一实体的图谱数据（当实体跨语言存在时）
- 输入已知名词时，图谱数据在 2 秒内展示
- 输入空白字符串或超短查询（<2 字符）时提示输入更多

**超出范围：**
- v1 不支持多名词对比搜索
- v1 不支持语音/图像输入


#### FR-2: 模糊语义搜索

[系统] 在精确名词匹配失败时 [条件：未命中已知实体]，可以进行语义相似搜索，返回最接近的实体结果。

**可验证结果：**
- 输入"深度学习之父"时返回 Hinton/LeCun 等人物的图谱
- 无任何近似匹配时显示"未找到相关概念" + 建议检查拼写或换词搜索


#### FR-3: 冷启动名词图谱构建

[系统] 在用户搜索一个尚未被索引的名词时 [条件：首次搜索]，自动从公开数据源构建该名词的知识图谱并缓存在数据库中。

**可验证结果：**
- 首次搜索一个新名词后，再次搜索同一名词时图谱立即返回（缓存命中）
- 图谱构建时间不超过 15 秒（含数据采集 + 分析）
- 如果 Wikidata 等主要数据源无数据，提示用户数据有限并展示 LLM 推理结果（标注置信度）

**特征级 NFR：**
- 图谱构建使用分层数据源策略：Wikidata API（免费结构化数据） → LLM 补充提取 → spaCy 备选
- 构建过程异步化：先返回已有数据 + 流式加载新增节点

### 4.2 关系图谱可视化

**描述：** 核心交互主视觉。以力导向图展示名词及其关联网络。节点可拖拽、缩放、点击展开详情。实现了 UJ-1, UJ-2, UJ-3, UJ-4。

**功能需求：**

#### FR-4: 力导向图谱展示

[系统] 可以 [能力：关联关系] 以力导向图（Force-directed Graph）方式展示名词节点的关联网络。核心节点居中，关联节点环绕分布。

**可验证结果：**
- 图谱在 2 秒内渲染完成（200 个节点以内）
- 节点默认展示 50 个主要关联，用户滚动/缩放时增量加载更多
- 用户可拖拽节点、缩放画布
- 鼠标悬停节点时弹出摘要卡片（名称、类型、置信度、一句话描述）
- 点击节点时该节点居中并展开其关联

**超出范围：**
- v1 不支持 3D 图谱可视化（Three.js 版本）
- v1 不支持节点手动编辑/固定位置


#### FR-5: 关联强度与类型可视化

[系统] 可以 [能力：关系呈现] 通过边的粗细/颜色/样式区分关联强度和关系类型。

**可验证结果：**
- 强关联（多源交叉验证）的边比弱关联（单一来源）更粗/更显眼
- 关系类型通过颜色编码区分（红色=影响、蓝色=隶属、绿色=创作、灰色=其他）
- 图例说明可展开/收起
- 低置信度关系以虚线展示，悬停时显示来源

**超出范围：**
- v1 不支持用户自定义边样式


#### FR-6: 节点详情展开

[用户] 可以 [能力：探索] 点击图谱中的任意节点，展开该节点的详情视图，包含其核心信息、关联摘要和关键时间点。

**可验证结果：**
- 点击节点后在当前图谱上/侧边展示详情面板
- 详情面板包含：名称、类型、描述、关键事实列表（带置信度）
- 详情面板底部显示「展开该节点的图谱」按钮
- 点击后当前图谱中心切换到新节点，原有节点成为分支


#### FR-7: 关联过滤

[用户] 可以 [能力：筛选] 按关联类型、置信度等级、时间范围过滤图谱显示内容。

**可验证结果：**
- 提供关联类型多选过滤器（影响/隶属/创作/发现/其他）
- 提供置信度滑块（高/中/低）
- 提供时间范围选择器
- 过滤后图谱实时更新，被过滤的节点和边淡化而非消失

### 4.3 演化时间轴

**描述：** 展示名词及其相关概念的演化历程。用户可拖拽时间滑块，查看不同时期的关键事件。实现了 UJ-2, UJ-3, UJ-4。

#### FR-8: 时间轴展示

[系统] 可以 [能力：时序呈现] 以可交互时间轴形式展示名词的演化关键里程碑。

**可验证结果：**
- 时间轴默认展示 5-10 个自动提取的关键里程碑
- 支持缩放到不同时间粒度（年/十年/世纪）
- 点击时间轴上的事件节点，展示该事件详情
- 无历史数据时显示「该概念的演化数据有限」

**超出范围：**
- v1 不支持多名词时间轴叠加对比


#### FR-9: 时间轴-图谱联动

[用户] 可以 [能力：联动探索] 拖动时间轴滑块，图谱上的节点和边根据选定时间范围动态显示或隐藏。

**可验证结果：**
- 拖动时间滑块时，图谱中不在该时间范围内的节点自动淡化
- 回到全时段时图谱恢复显示
- 时间轴与图谱的联动延迟不超过 500ms


#### FR-10: 关键里程碑自动摘要

[系统] 可以 [能力：自动摘要] 从概念的相关事件中自动提取 5-10 个关键里程碑节点，按时间排序展现。

**可验证结果：**
- 一个跨越 50 年以上的概念至少提取 5 个里程碑
- 里程碑标题简明（不超过 20 字）
- 每个里程碑附有简要说明和来源链接

### 4.4 AI 对话探索

**描述：** 在图谱语境下的 AI 问答界面。用户能追问、深挖、对比任意关系。实现了 UJ-2, UJ-3。

#### FR-11: 图谱上下文 AI 问答

[用户] 可以 [能力：智能问答] 在对话窗口输入问题，系统基于当前名词及其关联图谱的上下文调用 LLM 生成回答。

**可验证结果：**
- 问答响应以流式（WebSocket/SSE）展示，首字节 < 1 秒
- 回答引用图谱中的具体节点和边作为来源
- 回答分为两部分展示：图谱中直接存在的信息（高置信度）→ LLM 推理的信息（标注"推理得出"）
- 对话历史在当前名词浏览会话中保持上下文


#### FR-12: 图感知问答策略

[系统] 在 [条件：收到 AI 问答请求时] 采用三层检索策略（L1 图遍历 → L2 语义搜索 → L3 LLM 推理），优先利用图谱已有数据回答。

**可验证结果：**
- 图遍历（L1）命中时直接返回，不调用 LLM，响应时间 < 500ms
- 语义搜索（L2）命中时结合搜索结果，响应时间 < 2s
- 需要 LLM 推理（L3）时使用 WebSocket 流式输出
- 每个回答标注哪些内容直接来自图谱、哪些是 AI 推理

**特征级 NFR：**
- 每轮 AI 问答的 Token 消耗控制在合理范围（[ASSUMPTION: 目标 < $0.01/次，具体阈值需实测验证]）
- 使用语义相似缓存，相同/相似问题直接命中缓存

### 4.5 人物优先探索

**描述：** 遵循人物优先设计原则，人物节点在搜索结果、图谱展示和关联推荐中享有最高优先级。实现了 UJ-2。

#### FR-13: 人物识别与优先排序

[系统] 可以 [能力：实体分类] 识别搜索实体是否为人名。当识别为人物时，自动提升其展示优先级，展开其人物关系网络（人际关系、组织隶属、作品关联）。

**可验证结果：**
- 搜索人物名时，图谱中心自动展示该人物的关联网络
- 人物节点的交互层级高于非人物节点（首位展示、更详细信息）
- 人物关系类型具体化（师承/合作/竞争/隶属/亲属等）


#### FR-14: 人物递归探索

[用户] 可以 [能力：递归探索] 点击人物节点的关联人物，图谱中心切换到该人物，形成连贯的人物关系探索流。

**可验证结果：**
- 点击关联人物节点后，图谱中心切换到该人物
- 上一级人物的探索上下文保留在左侧/底部面包屑导航中
- 支持回溯到之前浏览过的人物

### 4.6 置信度与溯源系统

**描述：** 所有展示的信息标注置信度等级和来源链接。实现了从脑暴到 PRFAQ 一致强调的信任机制。

#### FR-15: 置信度标注

[系统] 为 [范围：所有实体、关系、事实] 标注置信度等级（高/中/低），并在 UI 中可视化区分。

**可验证结果：**
- 高置信度（多源交叉验证）无特殊标记
- 中置信度（单一权威来源）旁带 ⚠️ 标记
- 低置信度（LLM 推理/单一非权威来源）旁带 ⚠️ 标记并以虚线/暗淡色展示
- 置信度标注规则透明可查（提供「置信度说明」入口）


#### FR-16: 来源追溯

[用户] 可以 [能力：溯源] 悬停/点击任一条关系或事实，查看其来源信息。

**可验证结果：**
- 每个事实/关系可追溯到至少一个来源（数据源名称 + 链接）
- 多源信息显示所有来源
- 来源展示在详情弹窗中，点击可跳转到原始页面

## 5. 非目标 (Explicit)

- **用户注册墙** — MVP 不做强制注册登录，降低使用门槛 `[NON-GOAL for MVP]`
- **个人知识库** — 用户不登录，无法保存图谱和搜索历史 `[NON-GOAL for MVP]`
- **多名词对比** — v1 不支持在同一个视图中对比两个名词的图谱 `[NON-GOAL for MVP]`
- **3D 可视化** — 图谱使用 2D 力导向图，Three.js 3D 版本推迟到 Phase 2 `[NON-GOAL for MVP]`
- **未来推演模式** — 基于图谱的概率推理推迟到 Phase 2 `[NON-GOAL for MVP]`
- **用户上传数据** — 不允许用户上传自有知识库 `[NON-GOAL for MVP]`
- **移动端 App** — MVP 仅做响应式 Web，不做原生/混合 App `[NON-GOAL for MVP]`
- **Fork/分享** — 名词图谱的导出和分享功能推迟到 Phase 2 `[NON-GOAL for MVP]`
- **多语言全覆盖** — MVP 仅支持中英文，跨语言关联推迟到 Phase 2 `[NON-GOAL for MVP]`
- **利益关系分析** — 对人物关系的商业利益分析推迟到 Phase 3 `[NON-GOAL for MVP]`
- **企业级功能** — 批量导入、Cypher 查询 API、RBAC、审计日志 `[NON-GOAL for MVP]`

## 7. 成功指标

### 核心假设验证指标

- **SM-0: 核心假设验证** — 用户是否愿意用图谱化的方式探索知识？
  - 指标：用户在首次搜索后是否有第二次搜索行为（回访率）
  - 目标：7日回访率 > 20%
  - [ASSUMPTION: 此处 20% 为领域研究的经验基准，需验证]

### 主要指标

- **SM-1: 图谱加载时间** — < 2s（200 节点以内）。验证 FR-4。
- **SM-2: AI 问答首字节时间** — < 1s（WebSocket 流式）。验证 FR-11。
- **SM-3: 图谱实体准确率** — > 90%（用户反馈采样 + 自动交叉验证）。验证 FR-15, FR-16。
- **SM-4: 每次 AI 问答成本** — < $0.01/次。验证 FR-12 的成本控制策略。

### 次要指标

- **SM-5: 测试覆盖率** — > 80%（单元测试 + 集成测试）
- **SM-6: 服务可用性** — > 99.5%（Vercel + Docker）

### 反指标（不要优化）

- **SM-C1: AI 问答调用量** — 不要追求最大化 AI 调用次数。AI 调用增加运营成本，且低价值问题应通过图谱直接回答。反指标平衡 SM-4。

## 9. 跨切面 NFR

### 9.1 性能

- 图谱数据（100 节点级别）在 2s 内完成渲染
- AI 问答首字节响应 < 1s（WebSocket 流式）
- 图谱构建后台处理，不阻塞用户交互
- 图谱查询接口 P99 延迟 < 500ms（缓存命中）/ < 5s（缓存未命中需构建）

### 9.2 成本控制

- LLM API 是主要运营成本，必须从第一天开始控制
- 三层缓存策略：
  - L1: 浏览器缓存（Next.js `force-cache`）
  - L2: Redis 缓存（图谱查询 + LLM 语义相似缓存）
  - L3: Neo4j 持久化（热数据常驻内存）
- 分层检索策略（图遍历 > 语义搜索 > LLM 推理），上层问答不调下层
- 简单查询用小模型，复杂推理用强模型

### 9.3 数据质量

- 所有事实和关系标注置信度等级
- 多源交叉验证：同一个事实从多个数据源比对
- 不一致的数据标为「低置信度」并展示所有来源
- AI 回答标注哪些是直接从数据中提取的、哪些是推理得出的

### 9.4 隐私与合规

- 不存储用户搜索历史（除非未来用户登录后主动保存）
- 公开数据图谱不关联个人身份
- AI 回答页面标注「内容由 AI 生成」+ 置信度
- 提供用户数据导出和删除机制（即使 MVP 没注册功能，为后续准备）
- [ASSUMPTION: 中国运营需关注《生成式 AI 管理办法》的算法备案要求，EU AI Act 下本产品属于有限风险类别]

### 9.5 可观测性

- 请求链路追踪：记录图谱查询耗时、LLM Token 消耗
- API 延迟监控：各接口 P50/P95/P99
- 错误追踪：Sentry 集成前后端异常
- 成本监控：每日 LLM Token 消耗报表，超过阈值自动告警

### 9.6 技术选型约束

- 架构：MVP 采用模块化单体（Monolithic + 清晰模块边界）
  - 后续微服务拆分路径：模块边界 → 独立服务 → 服务网格
- 存储：MVP 仅用 Neo4j（利用其原生向量索引 SEARCH 子句），暂不引入独立 Milvus
- 部署：Docker Compose（后端）+ Vercel（前端）
- 技术栈：Next.js v16 + FastAPI + Neo4j 5.x + D3.js force-graph + vis-timeline

## 10. 审美与调性

### 设计原则（来自脑暴，经 PRFAQ 确认）

1. **渐进式信息密度** — 先给全景，想看细节再深入
2. **即时响应 + 流式加载** — 不要用户等
3. **智能筛选 + 关联强度排序** — 最重要的关系优先展示
4. **置信度标注 + 源头可追溯** — 每个事实都有根
5. **自动多粒度关键里程碑** — 5-10 个节点自动摘要
6. **免费探索 + 高级功能付费** — [ASSUMPTION: 商业模式待定，此处保留原则待替换]
7. **多源交叉验证 + 源质量评级** — 每条信息都可靠
8. **人物优先原则** — 人物作为默认探索入口

### 产品语调

- 产品名来源：**Logos**（λόγος）—— 古希腊语中的「言语」「理性」「知识」
- 核心比喻：「知识侦探」—— 你丢线索，它帮你把拼图拼起来
- 语调方向：专业但不学术、探索感而非工具感、不做作
