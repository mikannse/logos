# Sprint Change Proposal — 匿名搜索历史（快照回顾）

- **日期**：2026-07-31
- **触发人**：BMad
- **状态**：待批准
- **变更等级**：Moderate（需 PO/DEV 协同）

---

## 1. Issue Summary

### 触发原因

在搜索页调试会话中（消歧弹窗反复弹出、图谱空但时间轴有数据、搜索按钮外观三个问题的修复过程中），BMad 提出产品级需求：

> "我想要将历史搜索的结果保留下来供以后查看，然后之后如果搜索相同的名词，可以选择重新搜索，不然提示已有历史结果。"

即：**搜索历史保存与回顾**功能 —— 自动保存搜索结果的完整快照，重复搜索同一名词时提示"已有历史结果"，用户可选查看快照或重新搜索。

### 已锁定的范围决策（2026-07-31）

| 决策点 | 结论 |
|:---|:---|
| 身份/登录 | **暂不做登录**，直接匿名保存知识库快照 |
| 收费 | **免费**（本迭代），付费定位保留给 Phase 2 登录态完整个人知识库 |
| 保存粒度 | **完整图谱快照**（查询词 + 解析实体 + 图谱 nodes/edges + 时间轴 milestones） |

### 变更性质

将原本列为「非目标 / Phase 2」的"个人知识库"功能，以**匿名搜索历史（快照）**子集形式提前纳入本迭代。不推翻"无注册墙"原则，仅将"NGOAL 个人知识库"修订为"个人知识库（完整版）NGOAL + 匿名搜索历史 in-scope"。

## 3. Recommended Approach

**路径选择：Direct Adjustment（在现有计划内直接新增）**

- 不需要回滚任何已完成工作；
- 不需要缩小 MVP 范围——快照功能为增量能力，与现有搜索/图谱/时间轴正交；
- 匿名无登录设计避免引入认证体系，控制变更爆炸半径。

**工作量估算**：
- Story 4.1（后端存储）：1-2 人日
- Story 4.2（搜索流程接入 + 重复提示）：1 人日
- Story 4.3（历史 UI）：1-2 人日
- 合计约 **3-5 人日**，可并行（4.1 先行，4.2/4.3 依赖 4.1 接口）。

**风险评估**：

| 风险 | 等级 | 缓解 |
|:---|:---|:---|
| 匿名存储无限增长 | 低 | 单名词单快照（重复搜索覆盖）+ 提供删除接口 + 可加容量上限 |
| 重复搜索提示打断正常流程 | 中 | 弹窗仅在"已存在快照"时出现，首次搜索无感；默认动作"查看快照"不发起重建请求 |
| 快照数据过期 | 低 | 提供"重新搜索"重建最新数据并更新快照 |
| 与 Phase 2 登录态知识库衔接 | 低 | 快照序列化格式与未来共用（ADR-005） |

**时间线影响**：不影响当前 sprint 已排程的 Epic 1-3 收尾；Epic 4 可作为 sprint 尾部或下一 sprint 增量。

## 4. Detailed Change Proposals

### 4.1 PRD 修订（已应用）

**§5 非目标 — 个人知识库条目**
> OLD：`**个人知识库** — 用户不登录，无法保存图谱和搜索历史`
> NEW：`**个人知识库（完整版）** — 本迭代不引入登录与多用户；以匿名搜索历史形式实现子集：服务端自动保存搜索结果快照（查询词 + 完整图谱 + 时间轴），免费、无需登录、不关联个人身份。登录态个人知识库推迟到 Phase 2`

**NFR-10**
> OLD：`不存储用户搜索历史（除非未来用户登录后主动保存）`
> NEW：`不记录可关联个人身份的搜索行为。匿名保存搜索结果快照（查询词、解析实体、图谱节点/边、时间轴里程碑），快照与个人身份解耦、可导出可删除；不用于用户画像`

**§6.2 Out of Scope 表**：新增行 `匿名搜索历史 | 本迭代 | 无登录快照形式实现，免费`；原"个人知识库"行改"个人知识库（完整版）| Phase 2 | 完整版依赖登录态"。

**§4.7 搜索历史（匿名快照）**：新增 FR-17（自动保存）、FR-18（历史查看）、FR-19（重复搜索提示），含可验证结果。

### 4.2 Epics 修订（已应用）

- **新增 Epic 4：匿名搜索历史（快照回顾）**，含 Stories 4.1 / 4.2 / 4.3（见 §4.3）。
- FR Coverage Map 增加 FR-17/18/19 → Epic 4；Epic List 增加 Epic 4 条目。

### 4.3 Story 定义（新增）

```
Story 4.1: 后端快照存储服务
Given 用户搜索并解析出实体
When 搜索结果返回图谱与时间轴
Then 系统自动保存完整快照（查询词、实体、图谱 nodes/edges、时间轴、saved_at）
And 同一名词重复搜索时更新快照，不产生重复记录
And 提供 POST/GET /api/history、GET /api/history/{noun_id}（含 exists）、DELETE /api/history/{noun_id}
And 快照以 JSON 文件存储于 data/history/，零新增外部依赖
覆蓋需求: FR-17、NFR-10

Story 4.2: 搜索流程接入快照（保存 + 重复提示）
Given 用户搜索一个已存在历史快照的名词
When 搜索结果返回
Then 提示"已有历史结果"，提供两个选项：查看历史快照 / 重新搜索
And 查看历史快照直接加载已保存数据（不发重建请求）
And 重新搜索重建最新数据并更新快照
And 首次搜索（无历史快照）不弹出提示
覆蓋需求: FR-17、FR-19

Story 4.3: 历史记录 UI
Given 用户打开历史记录入口
When 查看历史列表
Then 显示历史列表（名词、解析实体、保存时间）
And 点击记录加载完整图谱与时间轴快照
And 支持删除单条历史
覆蓋需求: FR-18
```

### 4.4 架构修订（已应用）

- **ADR-005**：匿名 JSON 文件存储（`data/history/*.json` + `index.json`），快照为完整副本，独立于 Redis 缓存 / Neo4j 持久化。
- **架构原则 #5**：为 Phase 2 预留的序列化格式先落地为匿名快照格式，与未来登录态知识库共用结构。

### 4.5 前端设计修订（已应用）

- 路由新增 `/history`。
- §3.2.6 新增 HistoryList / HistoryItem / HistoryEmpty / DuplicateSearchDialog 组件设计。
- §4.1 新增重复搜索分支流程（查看历史快照 / 重新搜索）。
- §4.5 新增历史空状态与快照加载失败处理。
